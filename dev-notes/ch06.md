## 阶段 1:brainstorm 定稿(2026-10-20)

**用户关键原话(需求要点):**
- "我要用 **Superpowers 模式**让客服在一通会话里记得住前面聊过什么,把第一版的简单裁剪升级成**正经的上下文管理**。只管当前会话,不跨会话、不存用户画像。"
- 需求 1(三层 + 锚点):"按离当前这一轮的远近把历史切成三段。最近的留原文,**一个字都不压**;中间一层按规则截短,用户原话不动、客服答复只留开头几十个字、大块工具结果换成一行标识;最远的异步压成一段段梗概。两个锚点划边界,`summary_upto_msg_id` 标出摘要覆盖到哪条,`layer1_from_msg_id` 标出层 1 从哪条起,**降级只挪这两个 id、不搬数据**。梗概单开一张会话摘要表,不塞进逐条消息里。"
- 需求 2(异步摘要):"中间那层攒到超预算就在**后台**起一次摘要任务,把这一批压成新的一段**追加**进摘要表,边界追到层 1 起点,**全程不阻塞用户当前这轮回复**。梗概一段段攒、**压完不回头重写**,旧梗概只作背景给模型看、不参与合并……**触发看用量不数条数**,工具结果压根不落消息表,数条数看不见它涨。摘要提示词只提炼**事实与诉求**(问过哪款商品、报过的订单号手机号、明确诉求、还没解决的问题),对话里没出现的内容**一个字不许编**,寒暄闲聊不留,长度控制在几十到一两百字。"
- 需求 3(拼装顺序):"system 人设、红线和工具定义打头,这一段每轮都一样;接中间那层截短过的对话,再接最近几轮原文,然后是用户当前这句话;早期梗概和检索证据合成一条挂在用户这句之后。**梗概不许单独占一条 system**,上游模板会把所有 system 上提合并渲染,工具定义被挤到可变内容之后,前缀缓存整段作废。"
- 需求 4(预算):"token 预算从模型窗口倒推,不写死成常量……历史预算取「想留住的轮数 × 每轮稳态占用」和「窗口实际匀得出来的」两个数里小的那个,层 1 拿七成、层 2 拿三成。启动时自检一遍,连一轮都装不下就报警。**中文按字数折 token 的口径要和预算一起校准,只改一个净效果是反的**。"
- 需求 5(State):"`messages` 字段挂 `add_messages` reducer,各节点只管吐新消息、框架自动按顺序并入;State 里的完整历史靠 checkpoint 落盘留着,调模型前另外整理一份裁过、带摘要的精简版递进去,**完整历史和精简版各走各的、互不影响**。"
- 需求 6(可观测):"主力 Agent 打 `model_ctx`(摘要全文 + 滑窗逐条消息 + 窗口条数 + tokens 估算),指代消解/意图识别共用的历史打 `history_ctx`(摘要行 + 滑窗,**每轮必打**,不进 Agent 的闲聊兜底轮也看得到);后台摘要任务的**触发/开始/完成/跳过/失败**全留痕,带覆盖边界和耗时。"
- 需求 7(前端):"会话侧栏,列出该用户全部会话(新在前、首问预览、已摘要标记),点击切换并回载历史原文继续聊;「新对话」只是开新会话,旧会话仍在侧栏可切回;后端配两个只读接口……**侧栏加载失败静默降级不影响聊天**。"
- 本章不做:语义检索捞历史、主题重要度留关键事实(理论篇三种选法里另两层)、跨会话长期记忆、用户画像。
- 工作要求 5 条(与 Ch01–Ch05 同构):Superpowers 全流程 + 纯 Prompt/数据类用**标注样例/评估集**替代 TDD + `dev-notes/ch07.md` **每阶段实时追记(禁止收尾一次性补记)** + 第三方库**先过 Context7** + **技术选型定死、矛盾即暂停反馈禁止自行替换** + 完结交付(演示命令/测试结果/dev-notes 路径)。
