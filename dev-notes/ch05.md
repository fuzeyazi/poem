## 阶段 5 附加:终审修复

**终审结论:** **无 Critical;2 个 Important(其中 1 项含 Minor 合并)+ 3 个 Minor。** 本轮修复其中 **4 处**,Minor 5 **决定不修**。

### 修复 1(Important):纠错单 `poemId` 恒为 null
- **问题:** 前端 `chat.html` 提交纠错单时取 `lastTrace.poemId`,而 `_trace_payload` 此前不含 `poemId` → 纠错单永远写 `null`。
- **改法:** `main.py` 的 `_trace_payload` 追加 `"poemId": (final.get("slot_target") or {}).get("poemId")`(`slot_target` 里本就有 `poemId`,补上即闭环)。

### 修复 2(Important):续跑轮不再写空 user 行
- **问题:** 两段式续跑段的 `user_input` 是空串,`_persist_turn` 此前无条件往 `messages` 表写一条空 user 行,污染后续「挖知识」的数据源。
- **改法:** `workflow/nodes.py` 的 `_persist_turn` 里 `rows` 改为**仅当 `user_input` 非空白才追加 user 行**(`if (state.get("user_input") or "").strip():`)。

### 修复 3(Important-b + Minor 4):续跑轮的 trace/来源标识
- **问题:** 续跑轮跳过 classify,`route`/`intent` 被归零 → 前端轨迹显示「意图分流 -」,且 `_answer_source` 在无 `policy_hits` 时会误判为 `model`。
- **改法:** `main.py` 的 `_trace_payload` 把 `"route"` 改为 `final.get("route") or ("ruling" if final.get("subflow_kind") else "")` —— 用 `subflow_kind` 兜底成 `ruling`,使判定轮在 trace 与 `_answer_source` 语义一致。**未改 `_answer_source` 的判断逻辑本身**(其 `pending_subflow`/`complaint|chitchat` 分支与 `policy_hits`/`model` 分支,靠 route 兜底即可)。

### 修复 4(Minor 3,文档一致性):spec §6 字段表
- **问题:** §6 字段表还写 `query`,与 §11「不新增 `query` 字段」口径自相矛盾。
- **改法:** 该行改为 `resolved_input / query_changed`,并在说明里注明「复用 Ch04 既有 `resolved_input` 通道,不另开 `query` 字段(见 §11)」。
